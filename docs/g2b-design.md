# 나라장터 입찰 레이더 — 설계서

기존 "모집·신청 레이더"와 **별개 시스템**. 나라장터(g2b.go.kr) 입찰공고를 수집·분석해
우리가 붙을 수 있는 공고를 골라내고, 배점표 기준으로 예상 점수까지 산출한다.

작성 기준일: 2026-08-16

---

## 1. 왜 별개 시스템인가

기존 `모집·신청 레이더`는 설계상 입찰공고를 **노이즈로 규정**하고 있다.
`scripts/lib/exclude.mjs`의 공통 제외어에 `입찰`, `수의계약`, `민간위탁`이 들어 있다.

| | 모집·신청 레이더 | 입찰 레이더 |
|---|---|---|
| 사용자 행동 | 신청서 제출 | 제안서·견적 → 수주 |
| 핵심 정보 | 제목·부서·등록일·신청일자 | + 추정가격, 마감 **일시**, 계약방법, 지역·업종 제한, 배점 |
| 일 물량 | 수십 건 | 수백~수천 건 |
| 데이터 성격 | 전부 공개 정보 | 회사 실적·판정 결과 = **사내 기밀** |

→ 페이지·저장소·데이터를 완전히 분리한다.

`inqryDiv: 1` 을 쓰면서 주석에 "개찰일시" 라고 적어 둔 채 오래 굴러갔습니다.
고칠 때 이 표와 코드를 같이 보세요.)

| 파일 | 기준일 | 오퍼레이션 |
|---|---|---|
| `award.mjs` (작년실적 백필) | 3 = 개찰일시 | 낙찰목록 |

두 오퍼레이션을 다 봅니다. 개찰결과의 업체는 개찰에 들어온 업체이지 확정
낙찰자가 아니므로 화면에서 `선정` / `개찰참가` 로 구분해 적고, 업체별 집계는
낙찰 확정 건만 셉니다.

### 4.1 백필 (1회, 24개월)

```
공고     getBidPblancListInfoServcPPSSrch    공고일 기준, 월 단위 24회
```

- 진행 상태를 파일에 기록해 **중단되면 이어서** 진행
- 완료된 달은 건너뜀 → 몇 번을 다시 돌려도 안전
- 나라장터가 2025년에 공고번호 체계를 바꿈(`R+년도2+BK+순번8`).
  그 이전 데이터가 조회되는지는 백필 돌려보면 드러난다.

### 4.2 일일 증분

```
공고       최근 3일 (공고일 기준)
사전규격    최근 3일
낙찰·개찰   최근 7일 (등록일(1) 기준 — 뒤늦게 확정된 건 포함)

```

## 5. 저장 구조

화면이 **데이터가 박힌 단일 HTML**이라 저장 용량이 곧 화면 성능이다.
24개월 전량은 50MB를 넘어 브라우저가 못 연다. → **원본과 필터본을 분리한다.**

```
로컬 전용 (git 제외)              git + 화면
─────────────────                ──────────────
data/raw/                        data/g2b-posts.json
  2025-08.json                   data/g2b-awards.json
  2025-09.json                   data/g2b-analysis.json
  …  전량 · 수십 MB                 키워드 통과분만 · 몇 MB
  PC 하드에만
```

**키워드를 바꾸면 raw에서 몇 초 만에 재필터.** API 재호출이 없다.
"놓친 공고 리뷰"(키워드에 안 걸린 것 보기)도 raw가 있어서 공짜로 된다.

### 저장소

```
srajjihun/sraj  (public)   기존 모집·신청 레이더 — 그대로 유지
새 private 저장소            입찰 레이더 전체
```

**private이 필수인 이유**: 회사 실적·자격·판정 결과는 사내 기밀이다.
텍스트라 검색까지 잘 되어 노출 시 더 위험하다.
git은 파일 단위 공개/비공개가 없고, 한 번 push하면 히스토리에 남아 되돌리기 어렵다.

private이면 GitHub Pages를 못 쓰므로 **화면은 로컬에서 파일로 연다.**
PC에서 수집하는 구조라 자연스럽고, `file://`에서 별도 JSON을 못 읽는 CORS 문제도
데이터를 HTML에 박아버리면 사라진다.

### 파일 형식 원칙

```
사람이 손대는 것   →  마크다운   (회사정보, 키워드)
기계만 쓰는 것     →  JSON      (수집 데이터, 판정 결과)
제출용 증빙        →  PDF       (저장소 아님, PC 로컬)
```

회사 실적·자격은 **PDF를 올려주면 텍스트로 정리해 저장소에 넣는다.**
그 뒤로는 텍스트만 읽으므로 빠르고, PDF를 매번 파싱할 필요가 없다.

## 6. 키워드 관리

`config/keywords.md` 한 장으로 관리한다. 그룹 제목이 그대로 화면 탭이 된다.

```markdown
# 수집 키워드
## 창업
창업 / 스타트업 / 액셀러 / 인큐베이 / 벤처
## 일자리
일자리 / 취업 / 채용 / 진로 / 직무 / 인재양성
## 기업지원
기업지원 / 소상공인 / 중소기업 / 상권
## 쇼핑몰
쇼핑몰 / 온라인몰 / 판로 / 이커머스

# 제외 키워드
청소 / 경비 / 급식 / 시설관리

# 조달분류코드
80141988  전시회기획및대행서비스
```

**매칭 대상**: 공고명 + 조달분류명.
공고명만 보면 "○○몰 구축"이 '쇼핑몰'에 안 걸리는데 분류코드가 잡아준다.

**넓게 시작해 좁히는 것이 원칙.** 넓게 받아두면 나중에 좁히는 건 공짜지만,
안 받은 건 되돌릴 수 없다.

수집 분야는 **창업·기업지원·일자리**로 확정. (표본 100건 중 4~5건 = 월 200~500건 규모)

## 7. 문서 파이프라인

첨부파일에 파일명이 없는 경우가 있어 **앞 4바이트로 형식을 판별**한다.

| 형식 | 시그니처 | 처리 |
|---|---|---|
| PDF | `%PDF` | 바로 텍스트 추출 |
| HWPX | `PK` (ZIP) | 파이썬 XML 파싱 — **한컴 불필요** |
| HWP | `D0CF11E0` (OLE) | 한컴 COM → PDF → 추출 |

### 한컴 COM 자동화

HWP는 파싱하지 않고 **한글에게 PDF로 저장시킨다.** 표 구조가 그대로 보존된다.

```powershell
$hwp = New-Object -ComObject HWPFrame.HwpObject
$hwp.RegisterModule("FilePathCheckDLL", "FilePathCheckerModule")
$hwp.Open($src, "", "")
$hwp.SaveAs($dst, "PDF", "")
$hwp.Quit()
```

**초기 설정 1회 필요**: 한글이 외부 접근 시 띄우는 보안 팝업을 꺼야 한다.
자동화 중에는 아무도 눌러주지 않아 스크립트가 멈춘다.
`FilePathCheckerModuleExample.dll`을 고정 경로에 두고 레지스트리에 등록한다.
(대략 `HKCU\Software\HNC\HwpAutomation\Modules` — 한글 버전에 따라 다를 수 있어 실기 확인 필요)

건당 3~10초. 하루 8건이면 1분 내외.

**원본은 분석 후 버린다.** 추출 텍스트만 보관하고, 필요하면 URL로 재다운로드.

## 8. 판정과 채점

### 8.1 단계별 비용 구조

```
① 수집 (API)                  월 200~500건    비용 0
② 키워드 필터                                  비용 0
③ 공고문 PDF 다운 + 텍스트화                    비용 0  ← 전부 로컬
④ 자격 판정                                    비용 0
⑤ 제안요청서 정밀분석 (LLM)     하루 ~8건       ← 여기서만 비용 발생
```

비용 발생 지점이 맨 끝 소수 건으로 밀린다.

### 8.2 자격 하드필터

목록 API의 플래그만으로는 판정할 수 없다(업종제한 Y만 주고 내용을 안 줌).
**공고문 PDF 원문에서 읽는다.** 실측 예:

> 가. …공고일 전일부터 계약 체결일까지 본점의 소재지를 **부산광역시**로 하며…
> 나. …**기타자유업(행사대행업, 업종코드 9901)** 으로 등록을 필한 업체

판정 항목: 지역제한 · 업종(면허) · 직생 보유 품목 · 실적 요건 · 인력 요건

### 8.3 배점표 채점

**배점표는 공고마다 제각각이다.** 고정 스키마로 받을 수 없다.

```
공고 A   정량 20 / 정성 70 / 가격 10
공고 B   수행경험 10 / 이해도 20 / 역량 40 / 인력 10 / 사후 10 / 가격 10
```

→ 공고별 배점표를 **있는 그대로 저장**하고, 우리 프로필과의 매칭을 LLM이 판단한다.

### 8.4 LLM 사용 원칙

작업을 셋으로 쪼갠다. **"몇 점일 것 같아?"라고 물으면 그럴듯한 숫자를 지어낸다.**

```
(a) 추출   문서에서 배점표를 그대로 옮긴다. 못 찾으면 "없음"이라 답한다.
           추정 금지. 각 항목에 원문을 인용한다.
(b) 대조   추출한 요건과 회사 프로필을 맞춘다.
(c) 계산   산수는 코드가 한다. LLM에 시키지 않는다.
```

**모든 숫자에 근거와 출처가 붙어야 한다.** 검증 불가능한 점수는 시스템 전체의 신뢰를 무너뜨린다.
배점표를 못 찾았으면 "추출 실패"로 정직하게 표시한다.

### 8.5 단일 점수를 만들지 않는 이유

- 경쟁자를 개찰 전에는 알 수 없다
- 정성평가(제안서 품질) 비중이 대부분인데 이는 우리가 쓰기 나름이다
- **숫자가 나오면 사람은 믿는다.** 근거 없는 정밀도가 감보다 위험하다

→ 단일 점수 대신 **등급 + 근거 + 시나리오 표**를 제시한다.

```
제안서 등급   정량   정성     가격   총점    판정
우수          6     72~80    10    88~96   ✅ 통과
보통          6     58~68    10    74~84   ⚠️ 경계
미흡          6     ~52      10    ~68     ❌ 탈락
```

### 8.6 유사과업 판정

조달 분류가 3단계 계층으로 온다. 이것이 객관적이고 공짜인 유사도 척도다.

```
세분류 코드 일치  →  매우 유사
중분류 일치       →  유사
대분류 일치       →  관련 있음
```

다만 "유사"의 정의는 공고마다 다르므로(`창업 액셀러레이팅 관련 유사용역` 등),
**분류코드로 1차 추리고 → 공고가 명시한 정의를 읽어 최종 판정**한다. 앞은 공짜, 뒤만 LLM.

**인정/불인정 모두 이유와 함께 보여준다.** "3년 경과", "미완료" 같은 것을 알아야
증빙만 챙기면 되는 건을 놓치지 않는다.

### 8.7 작년 같은 공고 매칭

공고번호로는 못 잇는다(매년 바뀜).

| 단서 | 강도 |
|---|---|
| 수요기관 동일 + 공고명에서 연도 뗀 게 거의 같음 | 강함 |
| 수요기관 동일 + 분류코드 동일 + 금액대 유사 | 중간 |
| 분류코드만 동일 | 약함 — "유사 과업"이지 같은 사업은 아님 |

**못 찾으면 "작년 동일 공고 없음"이라 정직하게 표시**하고 시장 통계만 보여준다.
억지로 끌어다 붙이면 잘못된 판단을 부른다.

낙찰정보 등록이 늦어 아직 결과가 안 올라온 경우도 있다 → "낙찰정보 미등록"으로 구분.

## 9. 화면

파일 하나(`g2b.html`)에 데이터를 박아 로컬에서 연다. 화면 전환은 파일 내부에서 처리한다.

```
① 대시보드
     ├─[분석]───→ ③ 공고 상세
     ├─[자세히]──→ ④ 시장 리포트
     └─[목록]────→ ② 공고 목록 ─[분석]─→ ③

④ 시장 리포트
     ├─ 기관 클릭 → ⑤ 기관 프로파일
     └─ 업체 클릭 → ⑥ 업체 프로파일

⑦ 영업 시트 (별도 진입)
```

### ① 대시보드 — 1차

```
오늘      🟢유망 N  🟡검토 N  🔵사전규격 N  🔥D-3 N
          상위 3~5건 카드 (등급·예산·마감·예상점수·[분석])
진행 중    검토 N · 작성중 N · 제출완료 N              ← 3차
우리 판    유찰률 · 평균경쟁 · 낙찰률
          단골 업체 3 · 큰손 기관 3   [자세히→]        ← 2차
[전체 공고 목록 →]
```

**맨 위는 오늘 행동할 것.** 특히 `참가자격등록 마감 내일!` 경고는 첫 화면에 있어야 한다 —
이걸 놓치면 제안서를 다 쓰고도 못 낸다.

### ② 공고 목록 — 1차

```
탭      [전체] [창업] [일자리] [기업지원] [쇼핑몰]     ← keywords.md 그룹
필터    NEW만 · 마감임박만 · 사전규격만 · 🔍검색
표      등급 │ 제목 │ 수요기관 │ 예산 │ 마감 │ 예상점수 │ [분석]
        부제: 작년 ○○컨설팅 3.8억 · 5개사 경쟁         ← 2차
정렬    마감 · 예산 · 점수
```

**행 클릭 = 나라장터 원문** (기존 `ydp.html` 습관 유지), **[분석] 버튼 = 상세 화면**.
🔴 입찰불가 건에도 분석 버튼을 둔다 — "왜 안 되는지"를 봐야 납득이 되고,
"내년엔 되겠네" 같은 판단도 나온다.

### ③ 공고 상세 — 1차

```
판정 요약     등급 · 예상 82~90 · 커트라인 80
자격 판정     ✅❌ 항목별 + 근거 원문 인용 + 출처 페이지
배점표 채점   정량(계산 완료) / 정성(등급 구간) / 가격(공식)
              "1건만 더 인정되면 10점" 같은 실행 가능한 정보 포함
시나리오      우수·보통·미흡별 총점 → 통과 여부
과업 요약     기간 · 핵심 과업 · 산출물 · ⚠️리스크
작년 수주업체  업체·금액·낙찰률·경쟁 [업체 이력→]        ← 2차
원문          나라장터 · 첨부파일
```

### ④ 시장 리포트 — 2차

```
[현황]  전체 통계 · 💰돈 뿌리는 곳 · 🕳유찰 많은 곳
        📊경쟁 분포 · 💵금액대별 경쟁 곡선 · 📅계절성
[추이]  시장 규모 · 🔥뜨는 키워드 · ❄️지는 키워드
        발주 주체 변화 · 경쟁 환경 추이
[경쟁사] 키워드별 탭 → 상위 10개사
```

- **금액대별 경쟁 곡선**: 금액이 클수록 경쟁이 줄어든다(진입장벽).
  우리 실적으로 갈 수 있는 최대 규모가 승부처.
- **계절성**: 11~12월은 발주는 많고 경쟁은 적다(예산 밀어내기).
- **뜨는/지는 키워드**: 공고명 단어 빈도의 시계열. 정책 트렌드가 드러나고
  제안서에 쓸 키워드가 나온다. (추세를 보려면 최소 24개월 필요)

### ⑤ 기관 프로파일 — 2차

```
발주 건수·총액·평균 │ 평균경쟁·유찰률 │ 계약방식 분포
발주 시기 그래프    │ 진입 난이도(단골 편중도) │ 단골 낙찰업체
담당자 연락처       │ 발주 이력 전체
```

**발주 시기 패턴**이 특히 값지다. "3월·10월에 발주"를 알면 2월·9월에 접촉할 수 있다.

### ⑥ 업체 프로파일 — 2차

```
수주 건수·총액·평균 │ 주력 분야 │ 텃밭 기관
연도별 추세         │ 우리와 겹침도 │ 수주 이력 전체
```

**한계**: 낙찰 데이터는 이긴 업체만 보여준다. 진 업체는 수만 알고 누군지 모른다.
→ 사전규격 의견 작성 업체(`mkngCorpNm`)로 보완한다.

### ⑦ 영업 시트 — 2차

```
우선순위 │ 기관 │ 작년발주 │ 총액 │ 다음예상 │ 경쟁 │ 담당자
접촉 이력(수동) │ 엑셀 내보내기
```

우선순위 = 발주 규모 × 경쟁 약함 × 발주 시기 임박도.

## 10. 단계

| 단계 | 범위 | 조건 |
|---|---|---|
| **1차** | 수집(공고+사전규격) · 자격필터 · 배점채점 · ①②③ 화면 | 회사 프로필 필요 |
| **2차** | ④⑤⑥⑦ · 작년 수주업체 · 산업 동향 | 낙찰 백필 후 |
| **3차** | 파이프라인 · 회고 기록 | 팀 확산 시 |

**1차만 먼저 2주쯤 써보고 2차를 정한다.** 실제로 써봐야 뭐가 안 보게 되는지 알 수 있다.

### 3차 항목 설명

- **파이프라인**: 공고별 상태(`발견 → 검토중 → 참여결정 → 작성중 → 제출완료 → 낙찰/탈락`)와
  담당자. 핵심은 **불참 사유 기록** — 대부분의 회사가 이걸 안 남겨서
  몇 달 뒤 같은 공고를 처음부터 다시 판단한다.
- **회고 기록**: 예상 점수 vs 실제 결과. 쌓이면 "우리는 정성평가를 평균 8점 과대평가한다"가
  드러나고 시나리오 표를 보정할 수 있다.

**스키마에 `status` / `result` 필드는 1차부터 자리를 파둔다.** 나중에 붙이면 데이터를 다 고쳐야 한다.

## 12. 운영

기존 `collect.bat` / `collect-silent.vbs` 구조를 그대로 쓴다.
작업 스케줄러에 등록해 **아침에 PC를 켜면 자동 실행**된다.

> **주의 — `collect.bat` 은 공용 파일이다.**
> 이 PC에서는 나라장터와 별개로 *모집·신청 시스템*도 함께 돌아간다.
> 그래서 실제 로직은 시스템별 파일로 갈라져 있다.
> - `collect-g2b.bat` — 나라장터 전용. **이쪽만 수정한다.** (기존 파일 그대로, 로그는 `logs\g2b.log`, 손으로 `collect-g2b.bat 30` 실행도 가능)
> - `collect-recruit.bat` — 모집·신청 전용. 건드리지 않는다.
> - `collect.bat` — 로그·코드 동기화 후 위 둘을 `call` 하는 껍데기.
>
> 예전에 한 파일에 둘 다 들어 있었고, 나라장터 쪽에서 파일을 다시 쓰면서
> 모집·신청의 push 블록이 통째로 사라져 웹사이트가 며칠간 멈춘 적이 있다.
> 오류는 나지 않았고 아무도 몰랐다. 파일을 가른 이유가 이것이다.

```
08:50  PC 켬
08:52  공고 수집                 ~150건
08:53  키워드 필터               ~30건
08:54  공고문 PDF → 자격 판정     ~8건
08:56  제안요청서 → 한글 → PDF
08:58  배점표 추출 → 채점
09:00  완료
```
